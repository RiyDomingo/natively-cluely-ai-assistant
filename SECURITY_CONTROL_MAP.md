# Natively v2.8.8 Security Control Map

## Scope and method

This is a control-surface inventory for an authorised, local-only assessment of the public Natively v2.8.8 checkout. The initial packaged E2E campaign and its authorised F-001 remediation were completed locally on 2026-10-01; evidence and classifications are recorded in `FINDINGS.md` and `ADVERSARIAL_TEST_MATRIX.md`. Only the E2E authorization/containment controls were changed; other controls remain unremediated and untested unless explicitly noted.

The private `premium/` and `natively-api/` source trees are unavailable in this checkout. Controls implemented exclusively in those trees—especially server-side licence validation, revocation, subscription state, and hosted API authorization—can only be identified from their public callers and contracts. They must not be classified as working or bypassed until their implementation or a safe local mock is available.

Trust boundaries used below:

- **Renderer → main:** renderer-controlled values crossing Electron IPC into privileged Node/Electron code.
- **Local untrusted input → application:** files, browser DOM, transcripts, screenshots, URLs, and local network clients.
- **Application → provider:** content and credentials sent to AI, telemetry, update, or OAuth services.
- **Local process/profile → protected state:** environment variables and files writable by the current OS user versus keyring- or server-validated state.
- **Build/release → installed application:** source and artifacts crossing packaging, signing, notarization, and update boundaries.

## Cross-control observations to validate

1. **Availability, entitlement, and action authorization are separate controls.** Private module presence (`C-05`) must never be treated as proof of entitlement (`C-06`/`C-07`), and renderer UI state must never replace main-process action checks (`C-08`).
2. **The current trial action gate trusts local token presence and local expiry.** The hosted start flow may issue a signed token, but `isProOrTrialActive()` does not visibly validate that signature. Whether another private/server boundary compensates for this must be established with safe tests.
3. **The E2E packaged-state gap was reproduced and locally remediated.** Registration, synthetic capture, and common preload exposure now share main's unpackaged/opt-in decision; channel invocation is explicitly allowlisted. MacOS packaged-state and development fixtures pass. Windows, actual signed release artifacts, and paid-feature impact remain untested.
4. **IPC trust is largely handler-specific.** Context isolation reduces renderer compromise likelihood but does not authorize an IPC call. Sensitive handlers need their own sender, state, type, and entitlement checks.
5. **Local-user threats need explicit classification.** `safeStorage` and the fallback have intentionally different guarantees. Tests should distinguish an attacker who can only read/write profile files from one who can execute code as the same user; the latter can generally derive fallback secrets and alter an unpacked local application.
6. **Comments identify controls that are not live controls.** In particular, `ProviderRouter` documents that its circuit-breaker class is not wired into production. Tests must exercise actual call paths rather than infer enforcement from helper-unit coverage.

## Evidence and classification rule

The proposed tests are in `ADVERSARIAL_TEST_MATRIX.md`. Until a test is executed and reproduced, its result remains **Pending**. When execution is authorised, each row will be classified as exactly one of:

1. Control works as intended.
2. Control partially works.
3. Control can be bypassed.
4. Apparent bypass without meaningful impact.
5. Cannot safely complete from the available environment.

Static concerns are prioritization evidence only and are not labelled as bypasses.
